## 1. 当前基线

- 技术栈：React 19、TypeScript 6、Vite 8、Oxlint，纯前端并使用 `localStorage` 存档。
- 当前数据：四个系列均使用独立正式卡目，总计 2,547 张；盒规与公开赔率已进入 M2 配置，厂家未公开的签名短印明确保留为估算项。
- 当前引擎：先生成普通卡，再按产品盒规填入固定槽位；逐包赔率独立抽取，编号槽位按公开印量推导；包内按稀有度排序。
- 当前卡面：`CardFace` 支持显式真实图资源，缺图或加载失败时回退 SVG 球衣与缩写；平行、编号、RC、签名和物料效果独立叠加。
- 当前交互：支持点击/键盘翻卡、一键连翻与大卡暂停；卡包可横向拖动撕开；音效、音量、震动、卡面 tilt/holo 均有持久化设置并可安全降级。
- 构建基线：Node.js 24.19.0 + npm；`npm ci` 后可运行统一的 `npm run check`。
- 自动化现状：Vitest 覆盖引擎、存档迁移、四系列卡目和购买到收藏的整链路；构建包含 gzip/总产物体积门禁，关键 UI 另做桌面与移动端浏览器回归。

## 2. 执行原则

1. 先建立可重复验证的工程基线，再修改概率或卡池。
2. 卡池与概率数据先行，真实卡图依赖最终 checklist，避免重复收集素材。
3. 真实卡图采用“底图资源 + 平行特效叠加 + 绘制卡面回退”，不为每个平行单独存图。
4. 原有收藏数据必须可迁移；类型和 ID 变化不能让旧收藏册白屏。
5. 每个阶段保持可构建、可预览、可回退，不把全部升级压成一次大改。
6. 按用户确认的朋友间娱乐用途，可从互联网检索无水印高清球员摄影图；不要求原版卡设计或对应赛季，但必须记录来源并避免付费预览遮罩、明显水印和人物身份不确定的图片。
7. 素材检索、候选筛选、身份核对、裁切、压缩和音效挑选由执行代理完成；用户只在阶段成果完成后做整体视觉与听感验收。
8. 后续优化完成前不重新发布；本地验证通过且用户确认效果后，才生成新的线上版本。

## 3. 里程碑与实施顺序

### M0：工程基线与回归护栏

任务：

- 将 `tsx` 固定为开发依赖，增加 `simulate` 脚本，确保新环境可直接复现模拟结果。
- 为随机数注入可选种子或随机源，使概率测试可重复。
- 为 `ripBox`、盒保、卡数、编号范围和卡池过滤补充单元测试。
- 记录旧版 `PulledCard` 存档结构，并为后续数据模型升级准备版本号和迁移入口。
- 明确日常验证命令：lint、类型/生产构建、测试、概率模拟。

验收：

- 干净检出后，一次安装即可运行全部验证命令。
- 四个系列均满足卡数和盒保约束；固定种子结果可复现。
- 旧版收藏数据加载失败时有安全回退，不影响页面启动。

### M1：数据模型与官方 checklist 管线

任务：

- 定义统一的系列卡目结构，至少包含 `cardNumber`、球员、球队、国家、RC、卡种和子系列。
- 将球队、国家、系列和平行名称拆成卡面英文与 UI 中文字段。
- 建立 `src/data/checklists/{seriesId}.json`（或等价 TS 数据）与运行时索引。
- 编写 `scripts/import-checklist.ts`，将官方 XLSX/CSV 或规范文本转换为统一格式。
- 将签名、物料 checklist 与底卡 checklist 分离，取消“所有底卡球员都可出签”的假设。
- 先选 Prizm 英超做完整试点，数据源和人工修订都记录出处与日期。

验收：

- 导入器重复执行输出稳定，并能报告重复卡号、缺字段和未知球队。
- Prizm 英超卡号、RC 和子系列可与选定官方来源逐条核对。
- 卡面只展示英文；商店、按钮、筛选器仍可使用中文。
- 旧收藏中的 `playerId` 能映射到新卡目，无法映射时显示兼容卡面而不是丢弃。

### M2：真实概率与盒结构

任务：

- 为每个系列建立赔率数据：包赔率、单卡限量、盒保、案例卡和可用锚点。
- 编号平行按 checklist 数量和单卡印量计算总印量；无编平行按 `1:X packs` 换算。
- 将盒保和固定平行配比建模为盒槽位规则，概率只负责非固定槽位。
- 用官方赔率锚点反推或校准总包数；无法严格推导的字段标记 `estimated` 并记录依据。
- 扩展模拟脚本为至少 10,000 盒，输出实际 `1:X packs`、理论值、误差和盒保违规数。

验收：

- 有明确官方赔率的项目相对误差目标小于 5%。
- 所有系列卡数、盒保、编号范围均无违规。
- 估算项与官方项在数据和报告中可区分，不用人工权重冒充官方概率。

### M3：真实卡图双模式与素材管线

任务：

- 约定资源路径：`public/cards/{seriesId}/{cardId}[.auto|.relic].webp`。
- 在卡目中支持显式资源元数据；不只依赖猜测文件名，以便特殊卡和替换素材可控。
- 将 `CardFace` 拆成共享框架、真实图层和绘制回退层；加载失败自动回退。
- 平行折射、编号、RC、签名和物料效果作为独立叠加层，复用现有 CSS 主题。
- 图片使用固定比例、尺寸、WebP 压缩、懒加载与非阻塞解码。
- 实现 `scripts/assets.ts --todo` 与 `--process`：检查缺图、校验尺寸、裁切缩放、压缩和生成清单。
- 使用少量自制测试图覆盖底卡、签名图、物料图、缺图和加载失败五种路径。

验收：

- 同一张底图可正确展示多个平行效果，不需要复制素材。
- 缺图、错误 URL 或损坏图片均自动回退，拆卡流程不受影响。
- 单张成品图目标宽 500px、5:7、≤120KB；移动端无明显布局抖动。
- `?preview` 可集中查看真实图与回退图的全部关键组合。

### M4：Prizm 英超试点素材

前置门禁：已确认网页仅用于朋友间私下娱乐，不公开传播链接；本阶段素材随仓库保存。

任务：

- 按最终 checklist 与展示优先级生成 30–50 名大牌/新秀收图清单。
- 每张素材记录来源、获取日期、授权/使用备注和处理状态。
- 完成裁切、压缩、视觉质检与 URL 映射。
- 对银折、彩折、低编和 1/1 做桌面/移动端视觉调校。

验收：

- 试点清单覆盖率、失败回退率和总资源体积有可量化报告。
- 卡片文字可读，平行效果不遮挡球员、卡号、签字或物料区域。
- 构建产物和首屏加载体积增长在部署预算内。

### M5：拆卡体验升级

按低风险到高交互顺序实施：

1. 一键连翻：200–300ms 间隔，大卡自动暂停，可取消，组件卸载时清理计时器。
2. 移动端震动：能力检测、用户设置、无权限时静默降级。
3. 卡面 tilt/holo：指针与触摸输入，支持 `prefers-reduced-motion`。
4. 音效：首次用户交互后启用，提供静音和音量设置，不自动播放。
5. 撕包手势：鼠标与触摸统一用 Pointer Events，并保留键盘/点击替代入口。
6. 后续可选：peek、编号两段揭示、真实卡序和盒报告。

验收：

- 自动连翻不会重复入库、漏卡或跨包继续运行；大卡暂停逻辑有测试。
- 键盘、触摸、鼠标都能完成拆包；减少动态效果设置生效。
- 声音、震动和动效均有用户可控开关，能力缺失不阻塞核心流程。

### M6：扩展、性能与部署

任务：

- 按 M1–M4 流程扩展 Select 西甲、Obsidian、Topps Chrome 欧冠。
- 收藏册数据量增长后评估分页/虚拟列表、图片懒加载和存档容量。
- 增加构建体积检查、关键流程端到端测试和移动端视觉回归。
- 根据版权门禁选择：私有仓库 + Vercel，或公开代码 + 独立对象存储。
- 若迁移部署域名，验证 Vite `base`、资源路径、缓存策略和旧链接提示。

验收：

- 四个系列的数据来源、概率报告、素材覆盖率和估算项均可追踪。
- 主要桌面与移动端尺寸完成购买、拆包、收藏和刷新恢复测试。
- 部署环境不暴露不应公开的原始素材或凭据。

### M7：卡面全英文化

任务：

- 只约束卡片视觉层，商店、设置、拆包提示和收藏筛选等外围 UI 继续使用中文。
- 为系列、平行、球队和国家补齐英文显示字段；底层 ID、赔率配置和存档结构保持稳定。
- 卡面系列名使用完整英文产品名，例如 `2024-25 Panini Prizm Premier League`。
- 将 `底卡`、`银折`、`签名卡`、`球衣物料卡` 等卡面标签分别替换为 `Base`、`Silver Prizm`、`Autograph`、`Memorabilia` 等英文名称。
- 增加卡面文本测试，扫描所有可能渲染到卡片上的字段，禁止出现中日韩统一表意字符。

验收：

- 四个系列的绘制卡面、真图叠加层、编号、RC、签名和物料组合均不显示中文。
- 原有中文界面、概率、抽卡结果与旧收藏兼容逻辑不受影响。

### M8：高清球员摄影图与双尺寸管线

素材策略：

- 允许通过互联网图片搜索寻找球员任意时期的高清摄影图，不要求复刻原版卡片，也不要求对应当前系列赛季。
- 优先选择人物清晰、无遮挡、无明显水印、适合 5:7 竖版裁切的比赛或肖像照片。
- 同一球员只维护一套主照片资源，由不同系列的自绘卡框、平行折射和稀有特效复用。
- 原版高清卡图优先级最高；无原版卡图时使用球员摄影图；仍无可用照片时保留球衣剪影回退。

任务：

- 将球员摄影图与原版卡图拆成独立资源类型和解析优先级。
- 图片管线由单一 500×700/120KB 输出升级为缩略图 500×700 和大图 1000×1400 两档 WebP，并生成 `srcset` 所需元数据。
- 大图目标 180–300KB；按人物主体智能裁切，并提供焦点坐标人工式修正入口。
- 建立包含球员 ID、来源页面、获取日期、原始尺寸、处理结果和核对状态的素材清单。
- 第一批检索并逐张核对约 100 名核心球星、新秀和高频球员；确认视觉方向后再扩展。
- 检索、下载、去重、身份判断、裁切和压缩由执行代理完成；同名、身份不明或质量不达标的少量异常进入待处理清单，不阻塞可靠素材。

验收：

- 大卡在高分屏和桌面放大状态下无明显像素化，小卡不下载不必要的大图。
- 100 名试点球员身份正确、主体未被姓名栏或特效遮挡，来源和处理状态可追踪。
- 单张图片失败时仍自动回退，不影响拆包和收藏浏览。

### M9：真实拆包、翻卡与稀有提示音

任务：

- 用本地预录音频替换当前振荡器合成音，不在运行时依赖第三方音频网址。
- 拆包声音分为拖动过程中的轻微塑料褶皱、达到阈值时的塑料撕裂和完全打开时的包装松开声。
- 准备 3–5 个扑克牌翻动或纸卡滑动采样，播放时随机选择并轻微调整音高和音量，降低重复感。
- 稀有提示按普通编号、低编/签物、高等级案例卡、1/1 分级；提示音叠加在真实翻卡声后，不替代翻卡声。
- 对候选音效完成试听、剪切、降噪、响度统一和浏览器格式转换；总音效包目标控制在 1–2MB。
- 保留首次用户交互后解锁、音量控制、静音和不支持 Web Audio 时的静默降级。

验收：

- 撕包声音与拖动/开封动作同步，翻卡声音自然且连续操作不刺耳。
- 稀有等级听感可区分，但不会掩盖翻卡音或造成明显音量突增。
- Chrome、Edge 和移动浏览器验证通过；音频失败不阻塞拆卡。

### M10：全量扩展、质量复核与发布门禁

任务：

- 根据 M8 试点结果，将球员摄影图扩展至其余卡池；高置信度候选批量处理，异常候选逐项复核。
- 统计 1,069 名去重球员的照片覆盖率、回退率、素材体积和身份待确认数。
- 评估全量图片是否继续随仓库保存；若 Git 历史和部署产物过大，再迁移到独立对象存储并保持清单寻址。
- 完成桌面、移动端、高分屏、慢网络、自动连翻和稀有卡暂停的组合回归。
- 先提供本地或受控预览给用户验收；用户确认卡图清晰度和音效方向后才重新发布。

验收：

- 不存在已知的错人素材；模糊、严重遮挡、明显水印和错误裁切素材不进入发布版本。
- 构建、测试、概率模拟、资源清单和体积门禁全部通过。
- 未经用户明确确认，不覆盖当前线上版本。

## 4. 建议的提交切分

每个提交只解决一个可验证问题，建议顺序：

1. `chore: establish test and simulation baseline`
2. `feat: add checklist schema and importer`
3. `feat: migrate prizm checklist data`
4. `feat: derive odds and box collation from product data`
5. `test: validate simulated odds against product targets`
6. `feat: add real-image card face with fallback`
7. `chore: add card asset processing pipeline`
8. `feat: add prizm pilot card assets`
9. `feat: add auto-rip and accessibility controls`
10. 其余氛围体验与系列扩展分别提交。
11. `feat: enforce english-only card labels`
12. `feat: add responsive player photo assets`
13. `feat: replace synthesized cues with recorded sounds`
14. `feat: expand and verify player media coverage`

## 5. 每阶段统一完成标准

- `lint`、生产构建、相关测试和模拟检查全部通过。
- 新增数据有来源、日期、导入方式和校验结果。
- 新增 UI 同时验证桌面、移动端、键盘和减少动态效果模式。
- 不破坏既有余额与收藏存档；若结构变化，必须包含迁移或兼容路径。
- 文档与实际命令一致，新环境不依赖未声明的全局工具。
- 受版权约束的素材必须通过 M4 前置门禁后才能进入仓库或部署存储。
