## 2. 素材覆盖

- 四系列合计 2,547 张卡目。
- 当前显式素材映射 42 个，覆盖 40 张 Prizm 卡目；其中 39 张为 M4 实图，另有 M3 签名/物料测试变体。
- `broken.webp` 是保留的加载失败回归样例；其余 2,507 张未配置素材的卡目走绘制卡面回退。
- Select、Obsidian、Chrome 本阶段优先完成真实卡池，不批量复制不可靠图片；后续可逐系列使用同一 `assets --process/--todo` 管线补图。

## 3. 收藏与存档性能

- 收藏册过滤和排序后每批只渲染 48 张，用户按需继续加载，避免大收藏一次性创建全部卡面节点。
- `cr_collection` 升级为 v2 紧凑元组格式，只保存平行 ID，加载时从系列配置恢复完整平行对象。
- 旧版数组与 v1 对象继续兼容；未知版本、损坏条目、失效系列或平行会安全过滤。
- 1,000 张卡的回归测试要求 v2 体积小于 v1 的 55%。浏览器存储不可用或配额不足时不阻塞当前会话，并显示刷新后可能丢失的提示。

## 4. 构建与部署门禁

生产构建结果：

- JavaScript：756.40KB，gzip 133.76KB。
- CSS：20.81KB，gzip 5.66KB。
- `dist/`：1.84MB（包含约 1.06MB 的 M4 卡图）。

`scripts/check-build.mjs` 固定以下上限：单个 JavaScript gzip 350KB、单个 CSS gzip 80KB、完整 `dist/` 5MB。`npm run build` 自动执行门禁。

部署策略：

- 默认不设置环境变量，保留 GitHub Pages 的 `/card-ripper/` 基路径。
- 私有 Vercel 项目设置 `VITE_BASE_PATH=/`，使用仓库内 `vercel.json` 构建并回退到 `index.html`。
- 本阶段只完成可复现的私有部署配置，不主动创建公开部署；仓库与部署项目需保持私有，链接仅在朋友范围内分享。
