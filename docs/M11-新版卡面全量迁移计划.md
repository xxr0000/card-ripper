# M11 新版卡面全量迁移计划

> 状态：M11.1–M11.2 已完成；M11.3 进行中（试点清单与预览矩阵已完成，横向摄影素材待引入）
> 视觉基线：《新版卡面视觉约束》
> 前置结果：M0–M10 已完成；新版四张样例已通过方向确认
> 发布边界：全部阶段完成并经用户最终确认后再部署

> 临时发布例外（2026-08-19）：为尽快上线，用户授权新版卡面先复用 M10 旧球员图；
> 横向素材复核、试点验收与 M11.4–M11.6 仍按本计划保留，后续继续优化，不以本次发布替代。

## 1. 目标

将 `/?design-preview` 中确认的“等级边框 + 横向照片窗 + 独立信息区”设计迁移到项目中的
全部卡面，同时重建适合横向照片窗的球员素材输出。迁移后所有系列和卡种使用同一套版式规则，
差异由系列主题、稀有度、签名和物料数据驱动。

## 2. 影响范围

### 需要修改

- `CardFace` 正式渲染结构、卡面样式和图片加载逻辑；
- 稀有度到边框等级的统一映射；
- 签名、物料、签物和编号的信息区布局；
- 球员媒体元数据与处理脚本，增加横向衍生图和焦点信息；
- 四系列全部代表组合的预览与自动化测试；
- 素材审计、构建体积门禁和相关项目文档。

### 不修改

- checklist 内容、概率、盒保、抽卡排序与编号生成；
- `PulledCard` 的持久化字段和旧收藏迁移；
- 商店、钱包、拆包操作、音效和收藏筛选；
- 已确认的卡面英文、外围界面中文规则。

## 3. 执行原则

1. 先把样例代码整理成正式、数据驱动的共享组件，再开始批量处理素材。
2. 边框按稀有度统一，签名和物料按卡种组合，不为单卡编写专属 CSS。
3. 先审计现有原始来源图是否适合横裁；不适合的球员才重新检索，避免无意义重复下载。
4. 素材宁缺毋错。暂时没有合适横图时使用新版绘制回退，不继续使用近景硬裁或错人图片。
5. 每个阶段都保持正式拆包可用、旧收藏可打开，并有独立提交和可回退边界。
6. 在本地完成全量验收并获得用户确认前，不推送部署版本。

## 4. 分阶段计划

### M11.1：固化正式卡面组件

任务：

- 将评审样例中的版式抽成正式 `CardFace` 结构，删除生产/样例两套重复标记。
- 拆分共享层：卡体、顶部标识、照片窗、信息区、签名区、物料区和页脚。
- 将等级边框映射集中到单一配置或稳定类名，覆盖 Base、Shine、Numbered、
  Low-numbered、Super 和 One-of-one。
- 保留现有 tilt、holo 和 `prefers-reduced-motion` 降级；折射只作用于边框与底板。
- 保留图片失败回退，但回退层也必须使用新版照片窗版式。

代表样本：

- 四系列各一张 Base/Shine；
- 普通编号、低编、Super、1/1 各一张；
- 签名、物料、签物、RC、插卡各一张；
- 至少覆盖一名长姓名球员和一张无图片回退卡。

验收：

- 正式 `CardFace` 与确认样例在 `md` 尺寸保持一致。
- 所有代表组合没有文字、签名、物料或边框溢出。
- 旧的全幅图片和大面积斜线覆盖不再出现在正式卡面。

建议提交：`feat: adopt framed card face layout`

### M11.2：升级横向素材模型与处理管线

任务：

- 为球员媒体元数据增加横向小图、大图、焦点位置、适配状态和复核状态。
- 调整素材脚本，生成建议的 `720×480` 与 `1200×800` WebP 输出。
- 增加横图适配检查：原图比例、最小尺寸、人脸安全区、输出黑边、文件体积和重复内容。
- 保留旧竖图读取兼容，但新版正式卡面不得把竖图直接作为已验收横图。
- 明确完整卡面扫描图的处理：保留文件与元数据，不在新版照片窗内显示“卡中卡”。

验收：

- 同一素材处理命令可重复执行并产生稳定结果。
- 图片清单能区分“可由原图横裁”“需要重新找图”“无图回退”三种状态。
- 小卡不下载大图，现有构建体积门禁可追踪横图增量。

建议提交：`feat: add landscape player media pipeline`

### M11.3：四系列小批量迁移

任务：

- 每系列选取约 10 名高频球员，共约 40 名，覆盖不同球队、肤色、球衣和动作构图。
- 优先复用适合横裁的原始来源图；不适合的重新检索横向比赛照。
- 为每张图设置人工焦点并逐张检查 `sm`、`md`、`lg`。
- 在 `/?design-preview` 增加系列、卡种和稀有度矩阵，而不是只保留四张方向样例。

验收：

- 约 40 名试点球员全部填满照片窗，无黑边、错人、切脸或近景硬塞。
- 四系列的主题细节可区分，但等级边框判断一致。
- 签名认证小字、签名、物料说明、平行名称和编号均完整。

建议提交：`feat: migrate card face pilot across all series`

### M11.4：全量素材审计与批处理

任务：

- 以 M10 的 1,043 个独立卡面主体为基线，重新审计现有来源原图的横向适配性。
- 对可安全横裁的素材批量生成新衍生图；对近景、竖图、低清或主体靠边素材重新检索。
- 按展示优先级分批：顶级球星和热门新秀 → 高频球员 → 其余正式卡目主体。
- 每批输出覆盖数、重新检索数、回退数、待确认数、文件体积和失败原因。
- 继续执行身份、重复内容、尺寸、来源和孤儿文件审计。

完成标准：

- 全部 1,043 个主体都有明确状态，不存在未审计项。
- 已启用摄影图的主体全部通过身份与横裁复核；不合格素材不得进入正式映射。
- 无合适图片的主体统一显示新版绘制回退，不回退到旧全幅版式。

建议按批次独立提交：

1. `assets: migrate priority players to landscape media`
2. `assets: migrate remaining verified player media`
3. `chore: finalize landscape media audit`

### M11.5：全场景切换与回归

任务：

- 在拆卡页、自动连翻、包总结、收藏册小卡和收藏放大弹窗中启用新版卡面。
- 检查旧收藏中无 `cardId`、缺素材、损坏 URL 和旧球员 ID 的回退路径。
- 检查桌面、移动端、高分屏、减少动态效果、慢速加载和图片失败场景。
- 增加布局相关自动化检查：必要文本存在、卡面无中文、资源映射完整、代表组合可渲染。
- 运行 lint、测试、生产构建、概率模拟、媒体审计和体积门禁。

验收：

- 全站所有卡片入口均使用同一新版组件，不存在新旧卡面混用。
- `sm`、`md`、`lg` 无已知遮挡、溢出、黑边和切脸问题。
- 现有 48 项测试及新增测试全部通过；概率与存档结果不发生非预期变化。
- 图片和构建体积仍在门禁内，必要时先优化再进入发布验收。

建议提交：`test: validate framed card face migration`

### M11.6：用户验收与发布准备

任务：

- 提供受控预览，展示四系列与全部关键卡种，而不是只展示精选球星。
- 向用户明确列出仍使用绘制回退的主体及原因。
- 根据最终反馈只修正布局、焦点和素材，不在此阶段扩大功能范围。
- 用户确认后更新项目简介、执行状态和 M11 验收报告，再单独执行部署。

验收：

- 用户确认边框等级、照片构图、签名和物料布局可以应用到线上版本。
- 文档、素材审计数字和实际构建一致。
- 发布动作获得单独明确授权。

建议提交：`docs: record framed card face rollout results`

## 5. 建议执行顺序与提交边界

严格顺序：

`M11.1 → M11.2 → M11.3 → 用户中期确认 → M11.4 → M11.5 → M11.6 → 部署`

每个阶段单独提交。M11.4 数据量较大时按优先级拆为多个素材提交，避免组件逻辑与大批二进制图片
混在同一提交中。推送节奏应与提交一致，便于逐阶段回退和检查。

## 6. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 现有竖版来源无法横裁 | 重新检索横向比赛照；未找到时使用新版绘制回退 |
| 横图填满后仍切到脸或动作 | 为单图记录焦点；更换素材优先于不断调整通用 CSS |
| 签物卡信息密度过高 | 扩大命中信息区，按约束顺序缩小次要信息，禁止裁切签名与认证文字 |
| 四系列边框失去系列辨识度 | 稀有度控制主边框，系列只控制底板纹理和辅助色 |
| 全量素材显著增加仓库体积 | 用两档 WebP、替换旧衍生图而非长期双份保存；必要时再评估对象存储 |
| 完整卡面扫描图出现“卡中卡” | 新版渲染优先横向球员图，扫描图退出照片窗展示路径 |
| 批量处理引入错人 | 保留来源与身份审计，低置信度项目不自动启用 |
| 改版破坏旧收藏 | 不改变 `PulledCard` 存档字段，使用同一组件处理新旧记录 |

## 7. 完成定义

M11 只有同时满足以下条件才算完成：

- 正式卡面 100% 使用新版版式，所有入口不存在旧全幅卡面。
- 1,043 个独立主体全部完成横向素材状态审计。
- 已启用图片不存在已知错人、明显水印、黑边、切脸或低清素材。
- 签名、认证小字、物料说明、平行名称和编号在三档尺寸完整可见。
- 自动化检查、媒体审计、生产构建、概率模拟和存档回归全部通过。
- 用户完成全量受控预览验收，并明确同意后续部署。
