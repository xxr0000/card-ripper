# 真实化升级计划（卡图 · 卡池 · 概率）

> 目标一：把目前"代码绘制的致敬卡面"替换为**真实卡图**，效果参考
> 足球家公众号产品详解文章中的官方预览图（Panini/Topps 发布的 sell sheet
> 实卡图，如 25/26 Prizm FIFA 详解一文）。
> 目标二：让**卡池内容与抽取概率对齐真实产品**——收录名单按官方 checklist，
> 爆率按官方公布的包赔率与限量编号推算。
> 本文档只描述方案与计划，不涉及实现。

## 一、需求拆分

1. **底卡真图**：每张卡展示对应球员在该系列的真实卡面照片
2. **平行卡真图化**：银折、彩折、扎染等平行在真图基础上仍要有区分和特效
3. **签名 / 物料真图化**：签字卡、Patch 卡展示真实的签字版 / 物料版卡图
4. **素材管线**：图片的收集、命名、裁剪、压缩、入库要有一套可重复的流程
5. **回退机制**：找不到图的卡自动回退到现有绘制卡面，允许逐步铺开
6. **真实卡池**：每个系列的球员名单、卡号、新秀标记、插卡子系列与官方
   checklist 一致（而不是现在手挑的 ~40 人小名单）
7. **真实概率**：平行/插卡/命中的出现率与官方公布赔率、限量编号一致，
   拆盒结构（盒保、案例卡）与真实产品一致
8. **卡面去中文**：卡面上（含绘制回退卡面、签名）只出现英文，
   与实卡一致；中文只保留在网页 UI（商店、收藏册、按钮）中
9. **一键拆包**：翻卡页增加"一键拆开整包"，不想逐张点击时可快速开完一包

## 二、核心难点（先想清楚再动手）

### 1. 组合爆炸

卡图需要按「系列 × 球员 × 平行 × 类型」区分。以当前规模估算：

- 全量真图：4 系列 × ~40 球员 × ~10 平行 × (底卡/签名/物料) ≈ **数千张**，不可行
- 只收底卡真图：4 系列 × ~40 球员 ≈ **160 张**，完全可行

**结论：底卡收真图，平行用"真图 + 特效叠加"合成**（详见方案）。
真实平行卡本来就是同一张卡面换折射膜/配色，所以在真图上叠加现有的
CSS 折射/色框/编号特效，视觉上非常接近实卡，也是成本最低的路线。

### 2. 版权与托管

卡图版权属于 Panini / Topps（含球员肖像授权）。个人自用娱乐风险很低，但要注意：

- 当前仓库是 **public**，把成批卡图提交进去等于公开分发，风险升高
- 建议二选一：
  - **A（推荐）**：仓库转 private，部署从 GitHub Pages 换到 **Vercel**
    （免费支持私库，部署链接不变思路，照样能分享）
  - **B**：图片不进 git，放独立图床/对象存储（如 Cloudflare R2 免费额度），
    仓库里只存 URL 映射

### 3. 图片来源（按推荐度排序）

| 来源 | 特点 | 适用 |
| --- | --- | --- |
| 官方 sell sheet / 产品预览图（公众号文章、Panini/Topps 官网新闻页） | 质量最高、正面平拍、常带平行示例 | 每系列能拿到几十张，优先用于大牌 |
| eBay / COMC 已售挂拍实拍图 | 覆盖面最全，几乎任何"系列+球员+平行"都搜得到 | 补齐长尾球员；注意挑正面平拍、无手持的图 |
| 卡淘 / 闲鱼 / 卡吧帖子 | 中文环境方便搜索 | 备选补充 |
| Beckett / PSA Card Facts 数据库 | 有标准卡图但清晰度一般 | 校对卡编号、名称 |

> 收集方式建议**手动为主**（右键保存，按命名规范存放）。写爬虫批量抓取
> eBay 等站点有 ToS 风险且图片质量参差，不划算；160 张的量级手动一两个晚上能完成。

## 三、技术方案

### 1. 素材规范

```
public/cards/
├── prizm-epl/
│   ├── haaland.webp          # 底卡真图（去背景边框、只留卡面）
│   ├── haaland.auto.webp     # 可选：签字版真图（有就用，没有回退）
│   └── ...
├── select-laliga/…
├── obsidian/…
└── topps-ucl/…
```

- 命名约定式：`{seriesId}/{playerId}[.auto|.relic].webp`，代码零配置
- 统一规格：宽 500px、5:7 裁切、WebP 压缩（单张 ≤ 120KB，160 张约 15MB）
- 写一个素材脚本 `scripts/assets.ts`：
  - `--todo`：对照 `players.ts` × `series.ts` 输出缺图清单（收集进度表）
  - `--process`：把原始收集图批量裁切/缩放/压缩成规范格式（sharp 库）

### 2. 数据与组件改造

- `types.ts`：`PulledCard` 不用改（图片由 seriesId+playerId 推导）
- `CardFace.tsx` 双模式渲染：
  1. **真图模式**：`<img>` 卡图打底 + 叠加层（平行折射/色调滤镜、烫金编号、
     RC 标、签字层、Patch 窗）。平行色可用 CSS `filter: hue-rotate/saturate`
     或半透明渐变叠加模拟不同折射色
  2. **回退模式**：图片加载失败（onError）或清单中无图 → 走现有绘制卡面
- 平行特效复用现有 `CardFace.css` 的 sheen/refractor/glow 动画，只是叠在真图上
- 收藏册、拆卡流程、引擎**完全不用动**——这就是当初数据驱动设计的好处

### 3. 部署调整（若选方案 A）

1. GitHub 仓库转 private
2. Vercel 导入该仓库，自动构建部署（vite base 改回 `/`）
3. 得到新分享链接（`card-ripper.vercel.app`），旧 Pages 下线

> 补充：链接仅小范围给朋友使用的话，版权风险本身可控，
> 转 private + Vercel 属于"求稳"的可选项，而非必做项。

## 四、真实卡池与真实概率对齐

> 这是与"真实卡图"并列的第二条主线，建议**先做卡池和概率、后收图**：
> 收图清单依赖最终名单，先定名单可以避免返工。

### 1. 数据从哪来

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 官方 checklist（球员名单、卡号、RC、插卡子系列、平行清单与限量） | Panini/Topps 官网可下载的 checklist（xlsx/PDF）；Cardboard Connection 的 set 页面；Beckett 数据库 | 最权威，四个系列都能找到完整清单 |
| 包赔率（无编平行/插卡的 1:X packs） | 包装背面赔率表（odds）、官方 sell sheet；eBay 实拍包装图也能看到 | Topps 每系列都公布；Panini 部分公布 |
| 盒均结构（几折射、几编号、几签物） | sell sheet 的 box break 说明；足球家等媒体的详解文章（中文，最好读） | 用来定"每盒保底"与验收 |
| 限量编号（/199、/99…/5、1/1 的印量） | checklist 自带 print run | 编号平行的概率直接由印量推 |

### 2. 数据模型改造

- 卡池从"全局球员表 + 系列过滤"改为**每系列独立 checklist**：
  `data/checklists/{seriesId}.ts`（或 JSON），每条记录含
  `卡号 / 球员 / 球队 / RC / 子系列(base、插卡名)`。
  底卡规模会从现在的 ~40 人扩到真实的 **200-400 张/系列**（如 Prizm 英超
  底卡 300 张，覆盖全部 20 支球队）
- **录入方式**：手敲不现实。写一次性导入脚本
  `scripts/import-checklist.ts`：官方 xlsx/CSV → 统一 JSON。
  Cardboard Connection 的网页清单可复制成文本后由脚本解析
- 签名/物料 checklist 单独一张表（真实产品签名名单 ≠ 底卡名单，
  且每人有独立限量），大牌短印直接体现在印量数据里，
  现在的"tier 权重"近似逻辑可以删掉

### 3. 概率引擎改造

- 现在：拍脑袋的相对权重（weight）
- 目标：权重全部由真实数据推导，两类算法：
  1. **编号平行**：概率 ∝ 该平行总印量 = 单卡印量 × checklist 张数。
     例：紫折 /99 × 300 张底卡 = 29,700 张紫折在总印量中的占比
  2. **无编平行/插卡**：直接用包赔率（如"银折 1:2 包"→ 每包卡数换算成单卡概率）
- 总印量（分母）不公开，但可由**赔率反推**：已知某编号平行的
  1:X 包赔率 + 印量，即可解出全系列包数，其余平行概率随之而出
  （sell sheet 通常给出足够的锚点）
- 拆盒结构对齐：盒保命中数、每盒固定的折射/编号配比（如 Topps Chrome
  "每盒 2 银折 + 2 编号"）在盒生成逻辑中显式建模，而不只是全局概率
- **编号唯一性（可选加分项）**：真实世界每个编号只有一张。可在本地存档里
  记录已抽出的"系列+卡号+平行+编号"，重复抽到时重掷编号，
  让朋友的收藏册永远不会出现两张 "07/99" 同卡
- **验收方式**：扩展现有 `scripts/simulate.ts`，模拟 1 万盒，输出各平行
  的"1:X 包"统计值，与官方赔率表逐行比对，误差 <5% 视为达标

### 4. 对卡图计划的影响

- 名单扩到 200-400 张/系列后，"全员真图"不再现实，收图策略改为**分层**：
  - 大牌 + 热门新秀（每系列 30-50 人）：收真图
  - 其余角色球员：回退到绘制卡面（回退机制本来就是 P1 的一部分）
- 素材脚本的缺图清单（`--todo`）按 checklist 生成，并标注优先级
  （按球星热度排序，优先补高频展示的卡）

## 五、体验优化（小改动，随时可做）

### 1. 卡面去中文（对齐实卡观感）

现状盘点（哪里出现了中文）：

| 位置 | 现状 | 目标 |
| --- | --- | --- |
| 卡面球队/国籍行（`cf-meta`） | 中文（如"曼城 · 挪威"） | 英文（如 "Manchester City · Norway"，或球队名+三字国家码 "MCI · NOR"） |
| 卡面平行名（`cf-parallel`） | 中英混排（如"银折 Silver Prizm"、"底卡"） | 纯英文（"Silver Prizm"、"Base"） |
| 系列名（`cf-series` 页眉） | 中文（如"Prizm 英超"） | 英文（"Prizm Premier League"） |
| 签名 | 已是拉丁字母（"E. Haaland"），无需改 | 保持 |
| RC 标、JERSEY/PATCH、编号 | 已是英文/数字 | 保持 |

实现方向：

- 数据层做**双语字段**：`Player` 加 `teamEn`（或直接把 team 改英文、
  另加 `teamZh` 供 UI 用）；`Parallel` 与 `SeriesConfig` 加 `nameEn`
- 渲染规则：**卡面组件（CardFace）只取英文字段；网页 UI（商店、收藏册、
  筛选器、弹窗）继续用中文**，两边职责分清
- D1 换成官方 checklist 后，球员/球队/平行名天然就是英文原文，
  所以这一项如果排在 D1 之后做，工作量会更小（顺序建议见下表）

### 2. 一键拆一包

实现方向：

- 翻卡页（RipView）加"一键拆开整包"按钮：自动按当前顺序逐张翻开
  （每张间隔约 200-300ms 的连翻动画），命中/编号卡的全屏爆闪特效照常触发，
  翻完直接进入该包已翻卡的托盘视图
- 遇到大卡（特效等级 ≥3）时连翻**自动暂停**在该卡上，点击确认后继续——
  保留"压轴卡"的仪式感，避免一键把梅西签字"刷"过去
- 状态层只需在现有 `revealIdx/flipped` 之上加一个 `autoRipping` 定时器状态，
  卡片入收藏册的逻辑复用现有 `onCardRevealed`，引擎不动
- 顺手可加（可选）："跳过动画直接看整包结果"的极速模式，
  与"一键连翻"二选一即可，不必都做

## 六、线下拆卡氛围感优化（建议清单）

> 目标：尽可能还原线下拆卡的仪式感、悬念和"手感"。
> 按投入产出比分为三档，可挑着做，全部独立于 D/P 主线。

### 第一档：性价比最高，强烈建议（合计约 1 天）

1. **音效**（WebAudio，带静音开关）
   - 撕包的撕纸声、翻卡的"啪嗒"声、编号卡的金属音、签字/大卡的重音 chime
   - 声音是线下拆卡记忆里最强的组成部分，实现成本也低，优先级最高
2. **翻卡光影跟随（tilt/holo 效果）**
   - 卡面折射光随鼠标位置（手机用陀螺仪）偏转，像手里转动卡片看折射
   - 现有 CSS foil 层已具备基础，加一层随指针的 transform + 光斑即可
   - 这是"数码拆卡"最接近实卡把玩感的一招
3. **撕包手势**
   - 选包后不直接进入翻卡，而是出现完整卡包，**按住向右滑动撕开封口**
     （移动端手势/桌面拖拽），撕口逐渐裂开 + 撕纸音效
   - 把现在的"点击即开"变成有阻尼的动作，仪式感来源
4. **移动端震动反馈**（`navigator.vibrate`）
   - 翻到编号卡短震、大卡连震；成本极低，手机上效果拔群

### 第二档：明显加分，建议排期（合计约 1-2 天）

5. **搓卡/偷看（peek）**
   - 长按卡片一角可以慢慢"搓开"露出一角（clip-path 跟随手指），
     模拟线下慢揭大卡时"搓卡"的心跳感；放手回弹，点击才完全翻开
   - 与"一键拆包"互补：一个求快、一个求慢
6. **开盒动画**
   - 购买后先出现整盒：撕开塑封 → 掀盒盖 → 露出码放的卡包
   - 把"到货开箱"的环节补上，流程完整对应线下
7. **编号卡揭示顺序**
   - 翻开编号卡时先给编号特写（烫金 "07/99" 放大浮现）再落到卡面，
     模拟线下"先看编号再看是谁"的两段式惊喜
8. **包内卡序真实化**
   - 现在是严格按稀有度升序压轴；真实卡包是 base 在前、平行居中偏后、
     hit 通常倒数第二张（最后一张常是 base/广告卡"护垫"）
   - 按真实位置分布随机，偶尔 hit 提前出现反而更像真的
9. **拆盒日志与盒报告**
   - 每盒结束的总结页升级：本盒命中列表、稀有度分布、历史拆盒记录
     （"第 14 盒 Prizm，人品最好的一盒"）；数据已都在 localStorage，纯展示工作

### 第三档：彩蛋与延伸（选做）

10. **模拟市价与回本统计**：给每张卡按稀有度/球星热度标注模拟市价，
    盒总结显示"本盒拆出价值 ¥xxx（回本率 86%）"——线下拆卡的核心乐趣之一，
    但需要维护一份价格表（可按 tier+平行粗略生成），数据工作量中等
11. **晒卡图导出**：收藏册选一张卡生成精美分享图（canvas 导出 PNG），
    朋友拆到大卡可以直接发微信群炫耀——传播乐趣的闭环
12. **卡砖/评级壳视觉**：/10 以下和 1/1 在收藏册中自动带"磁吸卡砖"边框，
    大卡的"值得保护"感
13. **厚包彩蛋**：含物料卡的包在选包页有极其细微的厚度差异（阴影深一点），
    老玩家能"摸包"——争议玩法，真实 hobby 盒其实也有此传闻，当彩蛋
14. **桌面氛围**：拆卡页背景换成毛毡桌垫质感，托盘变成"卡堆"斜叠摆放

### 不建议做的

- **开箱 3D 化 / WebGL**：投入大、手机兼容风险高，CSS 3D 已够用
- **多人同时在线拆卡**：需要后端与同步，超出"分享给朋友玩"的定位

## 七、分阶段计划（更新版）

| 阶段 | 内容 | 产出 | 预估工作量 |
| --- | --- | --- | --- |
| E1 体验优化 | 一键拆包（连翻+大卡暂停）；卡面去中文可先做临时英文映射 | 拆卡更顺手、卡面纯英文 | 半天 |
| E2 氛围感一档 | 音效、tilt 光影、撕包手势、移动端震动 | 拆卡"手感"质变 | 1 天 |
| E3 氛围感二档 | 搓卡 peek、开盒动画、编号两段揭示、真实卡序、盒报告 | 仪式感与悬念完整 | 1-2 天 |
| D1 卡池对齐 | 四系列官方 checklist 收集 + 导入脚本 + 数据结构切换（球队/平行英文名随官方数据落定） | 名单/卡号/RC/签名表与实际一致 | 1-2 天（收集与校对为主） |
| D2 概率对齐 | 赔率/印量数据录入，引擎改为数据推导权重，模拟器对表验收 | 爆率与官方赔率误差 <5% | 1 天 |
| P1 组件改造 | CardFace 双模式（真图+叠加层+回退）；素材脚本 `--todo/--process` | 放一张测试图即可看到效果 | 半天 |
| P2 试点系列 | 选 **Prizm 英超** 收大牌+新秀 30-50 张底卡真图，跑通收集→处理→上线流程 | 第一个真图系列 | 1-2 晚（以收图为主） |
| P3 特效打磨 | 平行叠加调色、编号烫金、签字层位置适配 | 平行体验接近实卡 | 半天 |
| P4 全量铺开 | 其余 3 系列真图 + 大牌签字/物料真图（梅西、C罗、姆巴佩等 10-20 张） | 全站真图化 | 2-3 晚 |

依赖关系：**E1/E2/E3 相互独立、随时可做；D1 → D2 → P1 → P2 →
(P3 与 P4 可并行) → P5（可选）**。
D1/D2 先行的原因：收图清单、签名名单、图片优先级都由 checklist 决定，
先收图后改名单会造成返工。卡面去中文若等 D1 一起做可少写一份临时英文映射，
但如果想尽快改善观感，E1 先行也没问题。
若追求"体感提升最快"，推荐顺序：**E2（音效+光影+撕包）→ E1 → E3**，
之后再进入 D/P 主线。

## 八、风险与备选

- **收图缺口**：冷门球员某系列可能找不到图 → 回退机制兜底，不阻塞上线
- **图片风格不统一**（扫描/翻拍/渲染混杂）→ 素材脚本统一裁切+色调，验收时肉眼把关
- **体积增长**：全量后约 20-30MB → WebP + 懒加载（收藏册虚拟滚动可后续再说）
- **备选方案**：若收图太累，可折中为"真实球员照片 + 现有卡框设计"
  （只收球员肖像，不收卡图），素材少一个数量级，但离"实卡感"会远一些
- **checklist 获取不全**：个别系列官方 xlsx 可能撤档 → Cardboard Connection
  与 Beckett 双源交叉；实在缺的子系列先按现状近似，标注 TODO
- **赔率锚点不足**（Panini 部分系列不公布完整 odds）→ 用足球家/开盒视频的
  盒均统计做经验校准，达不到 <5% 的项放宽到"量级一致"并在文档中注明
- **底卡池变大后拆包体验变"淡"**（300 人名单里角色球员占比高）→
  这正是真实产品的体验，属于预期效果；若朋友觉得太淡，可加一个
  "热门队盒"之类的自定义玩法，但那是另一个需求，不混进本计划
